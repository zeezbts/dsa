Basic Terminology in Linked Lists

Core Elements

  • Node: The basic building block containing data and a link pointer.
  • Data: The actual value or payload stored inside the node.
  • Link / Next: The pointer storing the memory address of the next node.

Positions & Pointers

  • Head: The starting pointer pointing to the first node of the list.
  • Tail: The last node of the list, whose next pointer usually equals NULL.
  • NULL: A marker indicating an empty address, signaling the end of the list.

Key Terms & States

  • Traversal: Passing through each node sequentially from start to finish.
  • Overflow: An error state when memory is full and no new node can be added.
  • Underflow: An error state when trying to delete an item from an empty list.

Linked Lists

A linked list is a linear data structure where elements (nodes) are not stored in contiguous memory locations. Instead, each node points to the next using a memory address link.

There are four primary types of linked lists based on how the nodes connect to each other:

1. Singly Linked List

  • A singly linked list is a linear data structure consisting of a sequence of elements called nodes, Each node contains data and one forward pointer (next). Unlike arrays, these nodes are not stored in contiguous memory locations;
  • Direction: Supports forward traversal only.

operations

  • Insertion: Connect a new node to the next node in line, then point the current node to this new one.
  • Deletion: Change the pointer of the previous node to skip over the unwanted node and point directly to the next one
  • Search: Start at the beginning and check each node one by one down the chain until you find the right item.

Implementation Example

struct Node {
    int data;
    Node* next;
};
// Node initialization
Node* first = new Node{10, nullptr};
Node* second = new Node{20, nullptr};
first->next = second; // 10 -> 20 -> NULL

2. Doubly Linked List

  • A doubly linked list is a bi-directional linear data structure where each element, called a node, contains links to both the next node and the previous node.
  • Direction: Supports full bidirectional traversal (forward and backward).

operations

  • Search Follow the chain from either end, checking nodes one by one until it is found. (e.g., locating value 25 inside a list of files).
  • Insert At the Beginning, At the End and At the specific position
  • Delete From the Beginning, From End and From a Specific Position

Implementation Example

struct Node {
    int data;
    Node* next;
    Node* prev;
};
// Node initialization
Node* first = new Node{10, nullptr, nullptr};
Node* second = new Node{20, nullptr, first};
first->next = second; // NULL <- 10 <=> 20 -> NULL

3. Circular Singly Linked List

  • A circular singly linked list is a variation of a singly linked list where the final node points back to the first node, creating a continuous loop. Because of this structure, there is no NULL pointer at the end of the list.
  • Direction: Unidirectional forward navigation that loops continuously.

operations

  • Insert At the Beginning, At the End and At the specific position
  • Delete Removal from different positions

Implementation Example

struct Node {
    int data;
    Node* next;
};
// Node initialization
Node* first = new Node{10, nullptr};
Node* second = new Node{20, first}; // Loops back to first
first->next = second;               // 10 -> 20 -> (loops back to 10)

4. Circular Doubly Linked List

  • A circular doubly linked list is a bi-directional linear data structure where the first and last nodes are connected to each other, forming a complete, continuous loop.
  • Direction: Continuous loop traversal available in both directions.

operations

  • Insert At the Beginning, At the End and At the specific position
  • Delete Removal from different positions

Implementation Example

struct Node {
    int data;
    Node* next;
    Node* prev;
};
// Node initialization
Node* first = new Node{10, nullptr, nullptr};
Node* second = new Node{20, first, first}; // next/prev link to first
first->next = second;
first->prev = second;                      // first prev links to second

Applications of Linked Lists

  • Browser History: Managing back and forward page routing via Doubly Linked Lists.
  • Music Playlists: Sequential song queues with fluent track-to-track navigation.
  • Undo/Redo Tracking: Stepping back and forth through chronological state changes.
  • Image Viewers: Cycling next and previous photo assets cleanly inside galleries.
  • OS CPU Scheduling: Cycling active threads using round-robin Circular Linked Lists.
  • RAM Allocation: Managing available and active blocks inside system heap records.
  • Data Structure Engine: Acting as the dynamic foundation for Stacks and Queues.
  • Hash Chaining: Resolving indexing conflicts cleanly inside crowded Hash Tables.
  • Graph Modeling: Representing connection networks via structural Adjacency Lists.
  • Polynomial Math: Storing varying mathematical terms cleanly as separate dynamic nodes.

Advantages of Linked Lists

  • Dynamic Size: Grows and shrinks at runtime without needing an initial size.
  • No Memory Wastage: Eliminates pre-allocation since memory is allocated only when needed.
  • Easy Insertion/Deletion: Requires updating only pointers rather than shifting elements.
  • Easy Linear Implementation: Simplifies the creation of stacks and queues.
  • Flexible Storage: Elements do not require contiguous memory locations.
  • Highly Scalable: Efficiently manages large datasets by allowing node changes at any position.

Disadvantages of Linked Lists

  • Higher Memory Usage: Requires extra space to store pointer addresses for each node.
  • No Random Access: Element retrieval requires sequential traversal instead of index-based access.
  • Slow Traversal: Searching or iterating takes longer because it lacks direct memory indexing.
  • Restricted Reverse Traversal: Singly linked lists cannot go backward; doubly linked lists can but use more memory.
  • Complex Implementation: Needs advanced programming logic to manage pointers and nodes properly.
  • Inefficient for Small Data: Offers no performance benefit over standard arrays for tiny datasets.
