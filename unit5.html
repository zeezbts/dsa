PART A Finding an element in a collection

Searching is the process of finding a particular element, called the search key, in a collection of data. A collection may be an array, linked list, tree, file, or database.

A simple searching example

Given an array, the operation checks whether the key exists and returns its location.

Search key = 25

15 8 25 10 30

25 exists at index 2.

Objectives of searching

  • • Find whether an item exists.
  • • Locate the position of an item.
  • • Retrieve information linked to a key.
  • • Check duplicate values.
  • • Search records in files and databases.
  • • Support insert, delete, and update operations.

1. Linear Search

Checks elements one by one. It works on sorted and unsorted data and is simple, but slower for large collections.

2. Binary Search

Repeatedly divides the search area into halves. It requires sorted data and is much faster for large arrays.

Important terms

Term Meaning
Search key Element being searched.
Successful search The key is found.
Unsuccessful search The key is not found.
Position Location of the key in the collection.
Comparison Checking the key with an element.

Performance factors

  • • Number of elements
  • • Whether the data is sorted
  • • Type of data structure
  • • Searching algorithm used
  • • Number of comparisons
  • • Memory available

Sequential

Linear search compares every element with the search key from the beginning of the list until the key is found or the list ends. It is also called sequential search.

Search for 30

12 25 7 30 18

30 is found at index 3 after four comparisons.

Algorithm

LINEAR_SEARCH(A, n, key)

for i = 0 to n - 1
    if A[i] == key
        return i

return -1
Best:
O(1)
Average:
O(n)
Worst:
O(n)
Advantages and disadvantages
Advantages
Simple, easy to implement, works on unsorted lists, and needs no extra memory.
Disadvantages
Slow for large data and may compare every element.

Sorted only

Binary search repeatedly divides a sorted array into two halves. At each step, the middle element is compared with the key.

Search for 25 in a sorted array

5 10 15 20 25 30 35
  1. Mid = 20. Since 25 > 20, search the right half.
  2. New mid = 30. Since 25 < 30, search the left half.
  3. 25 is found at index 4.

Algorithm

BINARY_SEARCH(A, n, key)

low = 0
high = n - 1

while low <= high
    mid = low + (high - low) / 2

    if A[mid] == key
        return mid
    else if key < A[mid]
        high = mid - 1
    else
        low = mid + 1

return -1
Best:
O(1)
Average:
O(log n)
Worst:
O(log n)
Advantages and disadvantages
Advantages
Fast for large sorted arrays and requires very few comparisons.
Disadvantages
Data must be sorted; it is not convenient for linked lists.
PART B Organising data into a useful order

Sorting is the process of arranging data in a particular order. The most common orders are ascending order and descending order.

Ascending order

1020304050

Descending order

5040302010

Why sort?

  • • Makes searching faster
  • • Organises records
  • • Helps find duplicates
  • • Improves many algorithms
  • • Makes report generation easier

Key terms

Stable: keeps equal elements in their original order.

In-place: uses only a small amount of extra memory.

Adaptive: becomes faster when input is partially sorted.

Classification

Internal sorting: all data fits in main memory.

External sorting: data is too large to fit in memory.

Comparison sorting: uses comparisons between elements.

Non-comparison sorting: uses digits or values.

Bubble sort repeatedly compares adjacent elements and swaps them when they are in the wrong order. After each pass, the largest unsorted value moves to the end.

Sort: 5, 1, 4, 2

5142

Pass 1: 1, 4, 2, 5

Pass 2: 1, 2, 4, 5

BUBBLE_SORT(A, n)

for pass = 0 to n - 2
    swapped = false

    for i = 0 to n - pass - 2
        if A[i] > A[i + 1]
            swap A[i], A[i + 1]
            swapped = true

    if swapped == false
        break

Complexity: Best O(n) with optimisation; average and worst O(n²); space O(1).

Advantages and disadvantages

Easy to understand, stable, and in-place. However, it is very slow for large arrays because it makes many comparisons and swaps.

Insertion sort builds a sorted portion one element at a time. Each new element is inserted into its correct position among the previously sorted values.

Sort: 5, 2, 4, 6, 1

5 | 2 4 6 1

2 5 | 4 6 1

2 4 5 | 6 1

1 2 4 5 6

INSERTION_SORT(A, n)

for i = 1 to n - 1
    key = A[i]
    j = i - 1

    while j >= 0 and A[j] > key
        A[j + 1] = A[j]
        j = j - 1

    A[j + 1] = key

Complexity: Best O(n); average and worst O(n²); space O(1).

Advantages and disadvantages

Stable, in-place, and efficient for small or nearly sorted data. It becomes slow for large randomly ordered arrays.

Selection sort divides the array into sorted and unsorted portions. It repeatedly chooses the smallest element in the unsorted portion and places it first.

Sort: 64, 25, 12, 22, 11

Pass 1: 11 | 25 12 22 64

Pass 2: 11 12 | 25 22 64

Final: 11 12 22 25 64

SELECTION_SORT(A, n)

for i = 0 to n - 2
    minIndex = i

    for j = i + 1 to n - 1
        if A[j] < A[minIndex]
            minIndex = j

    swap A[i], A[minIndex]

Complexity: Best, average, and worst O(n²); space O(1).

Advantages and disadvantages

Uses little extra memory and performs only O(n) swaps. It is not adaptive and always performs O(n²) comparisons.

Merge sort is a divide-and-conquer algorithm. It divides an array into smaller pieces, sorts them recursively, and merges the sorted subarrays.

Sort: 38, 27, 43, 3, 9, 82, 10

Divide into small subarrays until each contains one element.

Merge: 27 38 + 3 43 → 3 27 38 43

Final: 3 9 10 27 38 43 82

MERGE_SORT(A, low, high)

if low >= high
    return

mid = (low + high) / 2
MERGE_SORT(A, low, mid)
MERGE_SORT(A, mid + 1, high)
MERGE(A, low, mid, high)

Complexity: Best, average, and worst O(n log n); extra space O(n).

Advantages and disadvantages

Guaranteed O(n log n), stable, and useful for linked lists and external sorting. It requires extra memory.

Quick sort selects a pivot and rearranges the array so smaller elements go left and larger elements go right. The same process is then applied recursively.

Sort: 10, 7, 8, 9, 1, 5

Choose 5 as pivot → 1, 5, 10, 7, 8, 9

Sort right side using pivot 9.

Final: 1, 5, 7, 8, 9, 10

QUICK_SORT(A, low, high)

if low < high
    p = PARTITION(A, low, high)
    QUICK_SORT(A, low, p - 1)
    QUICK_SORT(A, p + 1, high)

Complexity: Best/average O(n log n); worst O(n²); average space O(log n).

Advantages and disadvantages

Very fast in practice, usually in-place, and cache-friendly. Its performance depends on pivot selection and can degrade to O(n²).

Radix sort is a non-comparison algorithm that sorts integer values digit by digit. LSD radix sort starts with the units digit and moves left.

Sort: 170, 45, 75, 90, 802, 24, 2, 66

Units digit → 170, 90, 802, 2, 24, 45, 75, 66

Tens digit → 802, 2, 24, 45, 66, 170, 75, 90

Hundreds digit → 2, 24, 45, 66, 75, 90, 170, 802

RADIX_SORT(A, n)

find the largest element
place = 1

while largest / place > 0
    sort by digit at place
    place = place * 10

Complexity: O(d(n + b)), where d is digits and b is the base.

Advantages and disadvantages

Very efficient for suitable integers and fixed-length strings, but needs extra memory and is less suitable for negatives or floating-point values.

Heap sort uses a binary heap. For ascending order, it builds a max heap, repeatedly moves the root to the sorted end, and restores the heap property.

Max heap array: 20, 15, 18, 8, 10, 5, 12

Move 20 to the sorted area, then heapify the remaining values.

Final: 5, 8, 10, 12, 15, 18, 20

HEAP_SORT(A, n)

build a max heap from A

for end = n - 1 down to 1
    swap A[0], A[end]
    reduce heap size
    heapify the root

Complexity: O(n log n) in all cases; space O(1).

Advantages and disadvantages

Guaranteed O(n log n), in-place, and useful when worst-case time matters. It is not stable and often slower than quick sort in practice.

Shell sort improves insertion sort by comparing elements separated by a gap. The gap is reduced until it becomes 1.

Sort: 9, 8, 3, 7, 5, 6, 4, 1

Gap sequence for n = 8: 4, 2, 1

At gap 1, ordinary insertion sort finishes the ordering.

Final: 1, 3, 4, 5, 6, 7, 8, 9

SHELL_SORT(A, n)

gap = n / 2

while gap > 0
    perform gap-based insertion sort
    gap = gap / 2

Complexity: Depends on the gap sequence; worst case may be O(n²); space O(1).

Advantages and disadvantages

Faster than insertion sort for medium-sized data and uses no extra array. It is not stable and has less predictable performance.

Tree sort inserts values into a binary search tree. An inorder traversal—left subtree, root, right subtree—then returns the values in sorted order.

Input: 50, 30, 70, 20, 40, 60, 80

Build the binary search tree by inserting each value.

Inorder traversal: 20 → 30 → 40 → 50 → 60 → 70 → 80

TREE_SORT(A, n)

create an empty BST

for each element A[i]
    insert A[i] into the tree

perform inorder traversal

Complexity: Balanced tree O(n log n); skewed tree O(n²); space O(n).

Advantages and disadvantages

Inorder traversal naturally gives sorted output and supports dynamic insertion. A skewed tree can produce O(n²) performance.

Unit 5 · Final Topic

External sorting is used when data is too large to fit completely in main memory. For example, a 500 GB input file cannot be fully loaded into a computer with 8 GB RAM.

External merge sort

The most common external sorting technique has two major phases:

  1. 1. Run generation: Read blocks that fit in memory, sort each block, and write each sorted block as a run.
  2. 2. Run merging: Merge the sorted runs until one final sorted output file remains.

Worked example

Memory can hold four elements at a time.

Input: 45, 12, 89, 33, 7, 66, 20, 51

Run 1: 12, 33, 45, 89

Run 2: 7, 20, 51, 66

Final merge: 7, 12, 20, 33, 45, 51, 66, 89

Large input file
Memory-sized blocks
Sorted runs
Merge sorted runs → Final sorted file

Why external sorting is needed

  • • Input files are very large.
  • • Main memory is limited.
  • • Database files and logs need sorting.
  • • Data is stored on disks or external storage.

Main performance concern

External sorting performance depends mainly on disk reads, disk writes, available memory, number of runs, and number of merge passes. The main objective is to minimise disk input/output operations.
