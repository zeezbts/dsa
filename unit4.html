Part A – 2-Mark Questions and Answers

1. Define a tree.
A tree is a non-linear data structure made up of nodes connected by edges. It represents hierarchical relationships. A tree has no cycles.
2. What is the root of a tree?
The root is the topmost node of a tree. It is the only node that has no parent.
3. What is a leaf node?
A leaf node is a node that has no children.
Example: 
    A
   / \
  B   C
Here, B and C are leaf nodes.
4. Define a binary tree.
A binary tree is a tree in which every node has at most two children. They are called the left child and right child.
5. What is a full binary tree?
A full binary tree is a binary tree in which every node has either zero children or two children. No node has exactly one child.
6. What is a complete binary tree?
A complete binary tree is a tree in which all levels are completely filled except possibly the last level. The last level is filled from left to right.
7. What is a skewed binary tree?
A skewed binary tree is a tree in which every node has only one child. It may be:
  • Left-skewed
  • Right-skewed
A skewed tree behaves like a linked list.
8. What is a binary search tree?
A Binary Search Tree, or BST, is a binary tree in which:
Left subtree values < Root value < Right subtree values
9. What is tree traversal?
Tree traversal is the process of visiting every node in a tree exactly once. The main traversals are:
  • Preorder
  • Inorder
  • Postorder
  • Level-order
10. Write the order of preorder traversal.
The order of preorder traversal is: Root → Left subtree → Right subtree. It is also called NLR.
11. Write the order of inorder traversal.
The order of inorder traversal is: Left subtree → Root → Right subtree. It is also called LNR.
12. Write the order of postorder traversal.
The order of postorder traversal is: Left subtree → Right subtree → Root. It is also called LRN.
13. Which traversal gives sorted output in a BST?
Inorder traversal gives the elements of a Binary Search Tree in sorted order.
14. What is a threaded binary tree?
A threaded binary tree uses NULL pointer fields to store links to the inorder predecessor or inorder successor. It allows traversal without recursion or a stack.
15. What is an AVL tree?
An AVL tree is a self-balancing Binary Search Tree. For every node, the balance factor must be: -1, 0, or +1
16. Define balance factor.
The balance factor of a node is: Balance Factor = Height of left subtree − Height of right subtree
17. What are the AVL rotations?
The four AVL rotations are:
  • LL rotation
  • RR rotation
  • LR rotation
  • RL rotation
18. What is a heap?
A heap is a complete binary tree that follows a special ordering property. Types:
  • Max heap
  • Min heap
19. What is a max heap?
In a max heap, the value of every parent is greater than or equal to the values of its children. The largest element is at the root.
20. What is a min heap?
In a min heap, the value of every parent is less than or equal to the values of its children. The smallest element is at the root.
21. What is Huffman coding?
Huffman coding is a lossless data compression technique. It assigns:
  • Short codes to frequently occurring characters
  • Long codes to less frequently occurring characters
22. What is a graph?
A graph is a non-linear data structure consisting of vertices and edges. It is represented as: G = (V, E) where V is the set of vertices and E is the set of edges.
23. What is a vertex?
A vertex is a node in a graph. For example, in a graph representing cities, each city is a vertex.
24. What is an edge?
An edge is a connection between two vertices. For example, a road connecting two cities can be represented as an edge.
25. What is a directed graph?
A directed graph is a graph in which every edge has a direction. Example: A → B (This means the edge goes from A to B).
26. What is an undirected graph?
An undirected graph is a graph in which edges do not have a direction. Example: A — B (The connection can be travelled in both directions).
27. What is an adjacency matrix?
An adjacency matrix is a two-dimensional array used to represent a graph. If an edge exists between two vertices, the corresponding matrix position contains 1; otherwise, it contains 0.
28. What is an adjacency list?
An adjacency list stores each vertex along with a list of its adjacent vertices.
Example:
  • A: B, C
  • B: A, D
29. What is BFS?
BFS stands for Breadth-First Search. It visits vertices level by level and uses a queue.
30. What is DFS?
DFS stands for Depth-First Search. It visits a vertex and then explores as deeply as possible before backtracking. It uses recursion or a stack.
31. What is selection sort?
Selection sort repeatedly selects the smallest element from the unsorted portion and places it in the correct position. Its time complexity is: O(n²)
32. How many edges are present in a tree with n nodes?
A tree with n nodes has: n − 1 edges

Part B – 5-Mark Questions and Answers

  1. Explain the basic terminology of trees.

    Consider the following tree:

              A
        / | \
       B  C  D
         / \
        E   F
    • Root: The topmost node. A is the root.
    • Parent: A node having children. A is the parent of B, C, and D.
    • Child: A node below a parent. B, C, and D are children of A.
    • Sibling: Nodes having the same parent. B, C, and D are siblings.
    • Leaf: A node with no children. B, D, E, and F are leaves.
    • Internal node: A node having at least one child. A and C are internal nodes.
    • Degree: Number of children of a node.
    • Path: A sequence of connected nodes.
    • Depth: Distance from the root to a node.
    • Height: Length of the longest path from a node to a leaf.

  2. Explain the types of binary trees.

    • Full Binary Tree: Every node has either zero or two children.
    • Complete Binary Tree: All levels are full except possibly the last. The last level is filled from left to right.
    • Perfect Binary Tree: All internal nodes have two children and all leaf nodes are at the same level.
    • Skewed Binary Tree: Each node has only one child.
    • Balanced Binary Tree: The heights of the left and right subtrees are nearly equal.
    • Binary Search Tree: The left subtree contains smaller values and the right subtree contains larger values.

  3. Explain the linked representation of a binary tree.

    In linked representation, every node contains:

    • Data field
    • Pointer to the left child
    • Pointer to the right child

    Structure

    struct node
{
    int data;
    struct node *left;
    struct node *right;
};

    Example

              10
         /  \
        5    20

    The left pointer of node 10 points to node 5, and the right pointer points to node 20.

    Advantages

    • Dynamic memory allocation
    • Easy insertion and deletion
    • Suitable for irregular trees
    • No need for continuous memory

    Disadvantages

    • Extra memory is needed for pointers.
    • Direct access to a node is not possible.

  4. Explain array representation of a binary tree.

    Array representation stores binary tree elements in an array. Using index starting from 1:

    • Root is at index 1.
    • Left child of node i is at index 2i.
    • Right child of node i is at index 2i + 1.
    • Parent of node i is at index i/2.

    Example

              A
        /   \
       B     C
      / \
     D   E

    Array representation:

    Index 1 2 3 4 5
    Value A B C D E

    Advantages

    • Easy to implement
    • No pointer fields
    • Fast access
    • Suitable for complete binary trees and heaps

    Disadvantages

    • Wastes memory for sparse trees.
    • Not suitable for skewed trees.
    • The array size may need to be fixed.

  5. Explain how a general tree is converted into a binary tree.

    A general tree is converted using the left-child right-sibling method.

    Rules

    • The first child becomes the left child.
    • The next sibling becomes the right child.
    • Other children are connected through right links.

    General Tree

              A
       /  |  \
      B   C   D
         / \
        E   F

    Binary Representation

              A
         /
        B
         \
          C
         / \
        E   D
         \
          F

    Here: A.left = B, B.right = C, C.right = D, C.left = E, E.right = F. This method uses only two pointers per node.

    6. 7. Recursive Algorithms for Binary Tree Traversal

    All three recursive algorithms visit every node exactly once.

    Preorder Traversal

    Preorder(root) {
    if root != NULL {
        visit(root);
        Preorder(root->left);
        Preorder(root->right);
    }
}

    Inorder Traversal

    Inorder(root) {
    if root != NULL {
        Inorder(root->left);
        visit(root);
        Inorder(root->right);
    }
}

    Postorder Traversal

    Postorder(root) {
    if root != NULL {
        Postorder(root->left);
        Postorder(root->right);
        visit(root);
    }
}
    Time Complexity: O(n)

    8. Non-Recursive Algorithms for Binary Tree Traversal

    Iterative Preorder

    Preorder(root) {
    if root == NULL return;
    push root into stack;
    while stack is not empty {
        node = pop stack;
        visit(node);
        if node->right != NULL
            push node->right;
        if node->left != NULL
            push node->left;
    }
}

    Iterative Inorder

    Inorder(root) {
    stack = empty;
    current = root;
    while current != NULL or stack is not empty {
        while current != NULL {
            push current;
            current = current->left;
        }
        current = pop stack;
        visit(current);
        current = current->right;
    }
}

    Iterative Postorder (Using Two Stacks)

    Postorder {
    push root into stack1;
    while stack1 is not empty {
        node = pop stack1;
        push node into stack2;
        if node->left != NULL
            push node->left into stack1;
        if node->right != NULL
            push node->right into stack1;
    }
    while stack2 is not empty {
        node = pop stack2;
        visit(node);
    }
}

    Part C – 10-Mark Questions and Answers

    1. Explain binary tree traversal methods with an example and algorithms.

    Tree traversal refers to the systematic process of visiting every single node in a tree structure exactly once. Since trees are non-linear data structures, traversals can be carried out in different orderings.

    Example Binary Tree Structure

    The following sample binary tree is used to illustrate each traversal sequence:

                A
          /   \
         B     C
        / \   / \
       D   E F   G

    1. Preorder Traversal

    Preorder traversal processes the root node before moving to its subtrees. Ordering structure:

    Root → Left Subtree → Right Subtree

    Result Sequence: A B D E C F G
    Preorder(root)
{
    if root != NULL
    {
        visit(root);
        Preorder(root->left);
        Preorder(root->right);
    }
}

    Common Applications:

    • Creating an exact copy of an existing tree structure
    • Generating prefix expressions (Polish notation) from mathematical expression trees
    • Displaying directory listings and file systems hierarchically

    2. Inorder Traversal

    Inorder traversal sequences the nodes sequentially across the structure. Ordering structure:

    Left Subtree → Root → Right Subtree

    Result Sequence: D B E A F C G
    Inorder(root)
{
    if root != NULL
    {
        Inorder(root->left);
        visit(root);
        Inorder(root->right);
    }
}

    Common Applications:

    • Producing sorted, ascending output sequences from a Binary Search Tree (BST)
    • Generating infix mathematical expressions matching traditional arithmetic notation

    3. Postorder Traversal

    Postorder traversal processes the root node only after all its child subtrees are evaluated. Ordering structure:

    Left Subtree → Right Subtree → Root

    Result Sequence: D E B F G C A
    Postorder(root)
{
    if root != NULL
    {
        Postorder(root->left);
        Postorder(root->right);
        visit(root);
    }
}

    Common Applications:

    • Safely deleting a tree bottom-up (ensuring child nodes are cleared before losing reference to parent pointers)
    • Generating postfix expressions (Reverse Polish notation)
    • Expression tree evaluations inside compilers

    2. Explain recursive and non-recursive binary tree traversal.

    Binary tree traversals can be executed either using the system's implicit call stack via recursion, or manually using an explicit, user-defined stack data structure via iteration (non-recursive).

    Example Binary Tree

              1
        /   \
       2     3
      / \   / \
     4   5 6   7

    Recursive Traversal

    Recursive traversal relies completely on the runtime system call stack to store and manage prior activation frames during processing.

    • Preorder (Root → Left → Right): Visits root first, then recurses left, then right.
      Output: 1 2 4 5 3 6 7
    • Inorder (Left → Root → Right): Recurses left, visits root, then recurses right.
      Output: 4 2 5 1 6 3 7
    • Postorder (Left → Right → Root): Recurses left, then right, then visits root.
      Output: 4 5 2 6 7 3 1

    Non-Recursive Traversal

    Non-recursive strategies substitute recursion with an explicit user-allocated Stack data structure to track back-tracking references manually.

    • Preorder: Push the root node onto the stack. While stack is not empty, pop and visit the node, push its right child, and then push its left child.
    • Inorder: Traverse along the leftmost path pushing all intermediate nodes to the stack until a null pointer is reached. Pop a node, visit it, and move execution to its right child. Repeat.
    • Postorder: Can be achieved cleanly using two separate stacks to reverse the natural top-down visitation path into bottom-up postorder tracking.

    3. Explain BST operations: searching, insertion and deletion.

    A Binary Search Tree (BST) is a node-based binary tree data structure which possesses the following structural rule: for any given node, all keys in its left subtree are smaller than its key, and all keys in its right subtree are strictly larger than its key.

    Example BST Structure

    50 / \ 30 70 / \ / \ 20 40 60 80

    Searching Operation

    To trace and locate a value (e.g., 60):

    1. Compare 60 against the root node (50). Since 60 > 50, branching moves right to 70.
    2. Compare 60 against node 70. Since 60 < 70, branching moves left to 60.
    3. Node 60 matches the target value and is successfully found.
    Search(root, key)
{
    if root == NULL
        return NOT FOUND;

    if key == root->data
        return FOUND;

    if key < root->data
        return Search(root->left, key);

    return Search(root->right, key);
}

    Insertion Operation

    To safely insert a new value (e.g., 25), the tree must be scanned along its structural bounds until an available leaf leaf position is reached:

    • 25 < 50 → shift left to 30.
    • 25 < 30 → shift left to 20.
    • 25 > 20 → shift right. Since the right child of 20 is null, insert 25 as the right child.
    Insert(root, key)
{
    if root == NULL
    {
        create new node;
        return new node;
    }

    if key < root->data
        root->left = Insert(root->left, key);
    else if key > root->data
        root->right = Insert(root->right, key);

    return root;
}

    Deletion Operation

    • Case 1: Leaf Node: Disconnect and drop the link to the target node safely.
    • Case 2: Node with One Child: Bypass the node by linking its parent directly to its immediate child.
    • Case 3: Node with Two Children: Locate its inorder successor (the minimum element inside its right subtree). Replace the target node's data field with the successor's data, then recursively delete the duplicate node from the right subtree.

    Algorithmic Time Complexity Table

    BST Operation Average Case Complexity Worst Case Complexity
    Searching O(log n) O(n)
    Insertion O(log n) O(n)
    Deletion O(log n) O(n)

    Note: The worst-case runtime bound O(n) occurs when values are added in a fully sequential order, turning the tree into a linear skewed chain.

    4. Explain threaded binary trees in detail with traversal algorithm.

    A Threaded Binary Tree is a variant of a standard binary tree designed to optimize traversal by repurposing empty child links. In a standard binary tree, nearly half of all structural pointers are set to NULL, which wastes memory. Threaded trees replace these blank pointers with specific references called threads that point back up to structural ancestors.

    These specialized threads are configured to point directly to alternative positions:

    • The node's Inorder Predecessor (via the left pointer field if it would otherwise be NULL).
    • The node's Inorder Successor (via the right pointer field if it would otherwise be NULL).

    Structural Varieties

    • Left Threaded Binary Tree: Only unused left pointers are converted to point to their inorder predecessors.
    • Right Threaded Binary Tree: Only unused right pointers are converted to point to their inorder successors.
    • Double Threaded Binary Tree: Both left and right unused pointers are converted into threads simultaneously.

    Node Structure Configuration

    To distinguish between a normal child node reference and a thread pointer reference, boolean flag indicator variables must be added to the node definition:

    struct node
{
    int data;
    struct node *left;
    struct node *right;
    int leftThread;  // Evaluates to 1 if the left link is an inorder thread; 0 if a normal child
    int rightThread; // Evaluates to 1 if the right link is an inorder thread; 0 if a normal child
};

    Contextual Example

    Consider a simple tree containing three nodes:

    20 / \ 10 30

    The standard static Inorder Sequence for this layout is: 10, 20, 30. The tracking threads are applied as follows:

    • The right child pointer of 10 is normally NULL. It is converted to point directly up to its inorder successor: 20 (with rightThread = 1).
    • The left child pointer of 30 is normally NULL. It is converted to point directly up to its inorder predecessor: 20 (with leftThread = 1).
    • Outer boundaries that lack further predecessors or successors (the left link of 10 and the right link of 30) continue to point directly to NULL.

    Inorder Traversal Implementation

    Because these nodes point directly to their sequential neighbors, tracking routines can skip recursive stack loops entirely. Traversal uses a helper function to isolate the leftmost node, followed by sequential thread jumping:

    leftmost(root)
{
    while root->leftThread == 0
        root = root->left;

    return root;
}

ThreadedInorder(root)
{
    current = leftmost(root);

    while current != NULL
    {
        visit(current);

        // If a thread exists, step directly to the inorder successor
        if current->rightThread == 1
            current = current->right;
        // Otherwise, locate the leftmost node of the right child subtree
        else
            current = leftmost(current->right);
    }
}

    Trade-Off Evaluation

    Advantages Disadvantages
    • Eliminates recursion and stack memory requirements entirely.
    • Improves linear forward sequencing speeds.
    • Puts unused NULL memory slots to productive use.
    • Significantly increases code complexity for node insertion.
    • Significantly increases code complexity for node deletion.
    • Requires extra memory to track the structural thread flags.

    5. Explain AVL trees and their rotations.

    An AVL Tree (named after inventors Adelson-Velsky and Landis) is a self-balancing variant of a Binary Search Tree. It prevents performance degradation by ensuring the tree structure remains balanced during modifications.

    The core structural integrity is verified using a metric known as the Balance Factor (BF):

    Balance Factor = Height(Left Subtree) − Height(Right Subtree)

    To preserve structural balance, every individual node must maintain a balance factor of strictly -1, 0, or +1. Whenever an insertion or deletion pushes a node's balance factor to +2 or -2, structural balancing adjustments (rotations) are immediately triggered.

    1. Left-Left (LL) Case

    Trigger Condition: An insertion takes place within the left subtree of the target's left child node, causing a positive imbalance.

    Remedy Strategy: Execute a single Right Rotation directly on the unbalanced parent node.

    Unbalanced State:
          30 (BF = +2)
         /
        20
       /
      10
    → Right Rotate →
    Balanced Output State:
         20
        /  \
       10  30

    2. Right-Right (RR) Case

    Trigger Condition: An insertion takes place within the right subtree of the target's right child node, causing a negative imbalance.

    Remedy Strategy: Execute a single Left Rotation directly on the unbalanced parent node.

    Unbalanced State:
      10 (BF = -2)
        \
         20
          \
           30
    → Left Rotate →
    Balanced Output State:
         20
        /  \
       10  30

    3. Left-Right (LR) Case

    Trigger Condition: An insertion takes place within the right subtree of the target's left child node.

    Remedy Strategy: Execute a double rotation setup. First, apply a Left Rotation on the left child node, transforming it into an equivalent LL imbalance state. Then, apply a final Right Rotation on the unbalanced parent node to resolve the structure.

    4. Right-Left (RL) Case

    Trigger Condition: An insertion takes place within the left subtree of the target's right child node.

    Remedy Strategy: Execute a double rotation setup. First, apply a Right Rotation on the right child node, transforming it into an equivalent RR imbalance state. Then, apply a final Left Rotation on the unbalanced parent node to resolve the structure.

    Primary Engineering Advantages

    • Guarantees strict structural balance, preventing degradation into performance-bottlenecked paths.
    • Maintains highly optimized search bounds across large lookup data sets.
    • Guarantees operational worst-case performance limits stay clamped at a predictable O(log n) scale for searching, inserting, and deleting records.

    6. Explain heaps, heap operations and applications.

    A Heap is a specialized tree-based data structure that satisfies the heap property and must be a complete binary tree. A complete binary tree is completely filled at all levels, except possibly the lowest level, which is filled from left to right.

    1. Max Heap

    In a Max Heap, the key of the parent node is always greater than or equal to (≥) the keys of its children. The maximum element is always located at the root node.

    90 / \ 70 80 / \ / 40 50 60

    2. Min Heap

    In a Min Heap, the key of the parent node is always less than or equal to (≤) the keys of its children. The minimum element is always located at the root node.

    10 / \ 20 30 / \ / 40 50 60

    Array-Based Representation

    Because a heap is a complete binary tree, it can be efficiently stored inside a continuous array using 1-based indexing without wasting space on pointer addresses:

    • Parent Node Position: Found at index i / 2
    • Left Child Node Position: Found at index 2 × i
    • Right Child Node Position: Found at index (2 × i) + 1

    Core Heap Operations

    • Insertion: The new item is placed into the first available slot at the bottom-most right end of the tree to preserve the complete binary tree structure. It is then compared against its parent. If the ordering property is violated, it swaps positions with the parent. This upward adjustment continues until the property holds, a process known as heapify-up.
    • Deletion: Standard extractions remove the item at the root node. The root node is replaced by the last element at the bottom of the tree, and the last slot is dropped. The new root is then compared with its children and swapped with the largest child (in a max heap) or smallest child (in a min heap). This downward adjustment continues until the property holds, a process known as heapify-down.

    Primary Applications

    • Efficient implementations of Priority Queues
    • The Heap Sort algorithm, which guarantees O(n log n) sorting bounds
    • CPU and Job Scheduling architectures within operating systems
    • Graph routing optimizations like Dijkstra's Shortest Path algorithm
    • Continuous tracking for minimum or maximum threshold bounds

    7. Define a graph and explain graph terminology and representation.

    A Graph is a non-linear data structure comprising a finite set of nodes called Vertices (V) connected by links called Edges (E). It is mathematically formalized as G = (V, E).

    Contextual Example Graph

    A ----- B | | C ----- D
    • Vertices Configuration (V): {A, B, C, D}
    • Edges Configuration (E): {(A,B), (A,C), (B,D), (C,D)}

    Essential Graph Terminology

    • Vertex: An individual data node within the graph framework.
    • Edge: A connecting link or relationship pipeline between two distinct vertices.
    • Adjacent Vertices: A pair of vertices directly joined together by an edge.
    • Degree: The total count of structural edges directly incident to a specific vertex.
    • Path: A sequential route of adjacent vertices leading from a starting node to a target node.
    • Cycle: A closed path routing sequence that begins and terminates at the exact same vertex.
    • Directed Graph: A graph where every edge possesses a mandatory traversal direction (represented by arrows).
    • Undirected Graph: A graph where edges are completely bidirectional without directional constraints.
    • Weighted Graph: A graph where each edge contains an associated numerical value, cost, distance, or weight factor.
    • Connected Graph: A graph where a valid path exists between every single pair of vertices.

    Structural Graph Representations

    1. Adjacency Matrix

    A static 2D grid array of size V × V where cells contain boolean flags or weights showing if an edge directly spans from one vertex index to another.

        A B C D
A   0 1 1 0
B   1 0 0 1
C   1 0 0 1
D   0 1 1 0
    Space Complexity footprint: O(V²)

    2. Adjacency List

    An array of linked chains or arrays where every element index maps to a unique vertex, and its associated sequence tracks all its immediate neighbors.

    A: B, C
B: A, D
C: A, D
D: B, C
    Space Complexity footprint: O(V + E)

    8. Explain BFS and DFS graph traversal with an example.

    Graph traversal means visiting all the vertices in a graph systematically. The two fundamental traversal strategies are Breadth-First Search (BFS) and Depth-First Search (DFS).

    Example Graph Structure

    A / \ B C / \ \ D E F

    Breadth-First Search (BFS)

    BFS explores the graph level by level, visiting all neighbors of a node before moving to the next level of nodes.

    BFS Traversal Order (starting from A): A B C D E F
    BFS(start)
{
    create an empty queue;
    mark start as visited;
    insert start into queue;

    while queue is not empty
    {
        vertex = delete from queue;
        visit(vertex);

        for each adjacent vertex
        {
            if it is not visited
            {
                mark it visited;
                insert it into queue;
            }
        }
    }
}

    Primary Applications of BFS:

    • Finding the shortest path in an unweighted graph
    • Network broadcasting and peer-to-peer network routing
    • Level-wise searching and web crawling

    Depth-First Search (DFS)

    DFS explores as deeply as possible along each branch before backtracking to explore alternative paths.

    DFS Traversal Order (starting from A): A B D E C F
    DFS(vertex)
{
    mark vertex as visited;
    visit(vertex);

    for each adjacent vertex
    {
        if it is not visited
            DFS(adjacent vertex);
    }
}

    Primary Applications of DFS:

    • Cycle detection in directed and undirected graphs
    • Pathfinding and maze-solving algorithms
    • Topological sorting for scheduling dependency-based tasks

    Complexity Analysis for both BFS and DFS:

    • Time Complexity: O(V + E) where V is the number of vertices and E is the number of edges.
    • Space Complexity: O(V) to store the visited array and the auxiliary queue/stack.

    9. Explain selection sort with algorithm and example.

    Selection Sort is an in-place comparison-based sorting algorithm. It conceptually divides the array into a sorted part at the front and an unsorted part at the back. It repeatedly scans the unsorted section to find the minimum element and swaps it into its correct position at the boundary.

    Tracing Example

    Initial Array: 64 25 12 22 11

    • First Pass: The smallest element found in the entire array is 11. Swap 11 with the first element (64).
      Array state: 11 25 12 22 64
    • Second Pass: Look for the minimum in the remaining unsorted section (25 to 64). The smallest is 12. Swap 12 with 25.
      Array state: 11 12 25 22 64
    • Third Pass: Look for the minimum in the remaining section (25 to 64). The smallest is 22. Swap 22 with 25.
      Array state: 11 12 22 25 64
    • Fourth Pass: The remaining elements are already in sorted relative positions. No more swaps required.
      Final Array state: 11 12 22 25 64

    Algorithm

    SelectionSort(A, n)
{
    for i = 0 to n - 2
    {
        min = i;

        for j = i + 1 to n - 1
        {
            if A[j] < A[min]
                min = j;
        }

        swap(A[i], A[min]);
    }
}

    Time Complexities:

    • Best Case Complexity: O(n²)
    • Average Case Complexity: O(n²)
    • Worst Case Complexity: O(n²)

    Evaluation

    • Advantages: Simple to understand, uses zero extra memory (in-place execution), and performs a maximum of O(n) swaps (highly efficient when writes are expensive).
    • Disadvantage: Highly inefficient for large datasets due to its quadratic time growth complexity.

    10. Explain applications of trees.

    Tree data structures are highly useful across computer science because they establish non-linear, hierarchical relationships and optimize search and sort intervals. Key application areas include:

    1. File Systems: Operating systems organize files and folders within a multi-level tree hierarchy.
    2. Database Indexing: B-Trees and B+ Trees are used extensively within relational database indexes to manage disk reads and perform lightning-fast queries.
    3. Efficient Searching: Self-balancing Binary Search Trees (such as AVL trees and Red-Black trees) guarantee O(log n) boundary search limits.
    4. Sorting: Generating an Inorder traversal sequence from a valid Binary Search Tree outputs sorted data collections naturally.
    5. Expression Evaluation: Abstract syntax trees or expression trees are built by compilers to parse and calculate algebraic equations.
    6. Compiler Design: Parsing engines utilize parse trees and syntax trees to validate source code structurally against programmatic rules.
    7. Artificial Intelligence & Machine Learning: Decision Trees are built for complex data classification, branching paths, and analytical predictive forecasting.
    8. Data Compression: Huffman Trees are used to generate variable-length prefix codes for lossless data compression techniques.
    9. Priority Queues: Heaps are used to build priority queues where quick tracking of minimum or maximum records is required.
    10. Game Development: Evaluation engines construct game trees to model candidate decision moves in competitive games like Chess and Tic-Tac-Toe.
    11. Web Documents: Browsers evaluate and construct a tree framework out of raw markup text using the DOM (Document Object Model) for HTML and XML files.
    12. Network Routing: Enterprise routers implement minimum spanning trees to optimize path routing and prevent packet loops.
